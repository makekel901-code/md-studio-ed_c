# دمج الدروس والميزات من تجارب بناء التطبيقات السابقة

هذه الوثيقة تجمع ما أمكن استرجاعه من المحادثات السابقة وملفات PocketBuilder المرجعية وسياق MD Studio. وهي تفصل ما أضيف فعليًا في هذه الحزمة عما يحتاج مراحل لاحقة.

## قرارات بنيوية يجب الحفاظ عليها
- كل قسم رئيسي يحتفظ بمشروعاته وملفاته ومحركه وبياناته وسجله، ولا يكرر إعدادات القسم داخل الإعدادات العامة.
- الفصل بين مشروعات بناء Android بالكود/الملفات وبين مساحات مساعد الذكاء الاصطناعي التي تكتب الملفات دون بناء.
- النقل أو النسخ أو المشاركة بين الأقسام لا يتم بصمت: يجب كشف تعارض أسماء/مسارات الملفات وإظهار ما سيُستبدل قبل موافقة المستخدم.
- البناء لا يبدأ تلقائيًا بعد كتابة الملفات؛ له إجراء مستقل.
- لا يُعلن نجاح بناء أو اختبار اعتمادًا على شاشة أو خطة أو قالب؛ يلزم دليل ناتج حقيقي.
- تظل أوضاع AI الثلاثة (عادي/قوي/احترافي) مستقلة عن أسلوب توزيع مسؤولية التنفيذ بين الذكاء الاصطناعي والمحرك والمستخدم.
- لا يعاد إدخال المصمم المرئي والسحب والإفلات أو مولد الصور والفيديو؛ هذه العناصر مستبعدة من النطاق الحالي.

## ميزات من تجارب الأداة الخفيفة المعتمدة على GitHub
- تدقيق خطة التطبيق قبل التنفيذ، كشف المتطلبات المتعارضة والاعتماديات الناقصة.
- تحليل سجلات GitHub Actions وتحديد السبب الجذري لفشل البناء.
- اقتراح إصلاحات قابلة للمراجعة، مع إمكانية تطبيقها والتراجع عنها.
- إدارة الفروع وCommits وArtifacts وAPK وسجل المحاولات.
- مقارنة الناتج النهائي بالمواصفات الأصلية.
- إدارة التوقيع وملفات APK وإصدارات التطبيق.
- حفظ محادثات ومشروعات وتعديلات ونتائج البناء.

## ميزات من PocketBuilder 0.145 كمرجع تقني
- وكيل Gemini متعدد الأدوات.
- مسارات بناء محلية تعتمد أدوات Android/Java وأدوات موارد وDEX وتوقيع APK.
- Maven وإدارة مكتبات.
- تشغيل التطبيق وبعض اختبارات UI والتشخيص.
- تكاملات GitHub والويب والمكتبات.
- التحليل المرجعي السابق لم يثبت كل مسارات API أو كل الوظائف المعلنة باتصالات حية؛ لا تُعرض كتكاملات إنتاجية قبل إعادة التنفيذ والاختبار.

## ميزات من مشروع واجهة الاختبار/التطوير السابق
- واجهة منظمة إلى أقسام مستقلة، مع شاشة حالة واضحة لكل مهمة.
- إبقاء المحادثة كمركز تحكم بدل إجبار المستخدم على التنقل بين الشاشات أثناء التنفيذ.
- إظهار حالة المهمة الفعلية، مراحل التقدم، ونتيجة البناء فقط بعد وصول ملف APK.
- اختبار التطبيق المثبت فعليًا عند توافر جهاز/صلاحية مناسبة، وجمع الأدلة وربط الخطأ بمصدره.
- الحفاظ على الفصل بين الواجهة والمنطق والتخزين والخدمات، واختبار التثبيت والتشغيل والتحديث.

## ما أضيف فعليًا في تحديث Alpha 09 الحالي
- تبويب مساعد ملفات مستقل بمساحات بيانات منفصلة عن مشاريع Gradle.
- أوضاع تنفيذ مساعد الملفات الأربعة: ذكاء اصطناعي كامل، العقل المركزي، تنفيذ مشترك، ويدوي.
- معاينة ملفات قبل التطبيق، اختيار الملفات في الوضع المشترك، نقطة استعادة، وتراجع.
- تعديل خطة المدير الهندسي بصيغة JSON قبل الموافقة، مع التحقق من أن كل أداة مسجلة وأن نقطة الاستعادة موجودة قبل أول تعديل.
- لوحة تقدم حقيقية للمدير الهندسي: الوقت المنقضي، عدد الخطوات المكتملة، الخطوة الحالية، إيقاف مؤقت واستكمال وإيقاف تعاوني بين استدعاءات الأدوات.
- ألوان هوية متعددة للمظهر العام.
- ربط أزرار استيراد مشروع ZIP واستيراد حزمة أدوات البناء بالـ launchers الموجودة.
- إعدادات مركزية تعرض قواعد قبول صريحة دون تكرار إعدادات الأقسام.

## أولويات لاحقة غير مدعاة التنفيذ في هذه الحزمة
1. محركات ترجمة حقيقية لـ Java وKotlin وC++/NDK، وتحديد اللغة الرابعة المنسوبة إلى AMD Studio بعد فحص APK الأصلي.
2. مدير أدوات Toolchain قادر على تنزيل/تثبيت وإدارة إصدارات JDK وGradle وSDK وBuild Tools وNDK وCMake، مع اختيار محلي أو سحابي حسب توافر الأدوات.
3. مدير هندسي متعدد الوكلاء مع عقود أدوات مستقلة لكل وكيل، ومنع تعارض الكتابة بين الوكلاء.
4. محرك اختبارات وظيفية وواجهة آلية على جهاز/محاكي، مع تقارير أدلة وإصلاح وإعادة اختبار.
5. محرر كود متقدم مع مقارنة تغييرات سطرية، تحليل رموز، بحث شامل، وإدارة تعارضات الملفات.
6. دعم مزودين ونماذج AI متعددة، وإدارة حصص وتبديل موثق بين المزودين.
7. تشغيل خلفي موثوق للمهام واستعادة حالة التنفيذ بعد إغلاق الواجهة أو إعادة تشغيل التطبيق.
8. نموذج محلي مدمج داخل APK عبر JNI/NDK، دون الاعتماد على Termux؛ هذا يتطلب بناء مكتبة native لكل ABI وإدارة تنزيل النموذج ومساحة التخزين واختبار الأداء والذاكرة.
9. استكمال دورة GitHub: فروع مستقلة، مقارنة commits، سجل Actions كامل، وتنزيل artifacts وإدارة APK دون فتح صفحة خارجية حيث تسمح واجهات GitHub.
10. واجهة نقل/نسخ بين الأقسام مع كشف التعارضات وموافقة المستخدم، وسجل تغييرات شامل.
11. تشغيل خلفي دائم عبر WorkManager/خدمة مناسبة مع استعادة المهمة بعد إغلاق التطبيق؛ عناصر الإيقاف الحالية تعاونية بين الأدوات ولا تقطع طلبًا شبكيًا/أداة قيد التنفيذ فورًا.

## قاعدة التنفيذ
أي ميزة مستقبلية تُربط بمحرك حقيقي وتُظهر حالتها ومتطلباتها وحدودها. لا تُضاف أزرار شكلية ولا تُعرض موصلات عامة على أنها خدمات مكتملة.
